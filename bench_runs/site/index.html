What is a synergy for a coding agent?
Finger-coordination abstractions for agent-written dexterous policies

67 Claude agents · UR5e + Tesollo DG5F-S (20 DOF) · 12 tasks · Newton / MuJoCo-Warp
MethodResultsVideosLimitations
Abstract In reinforcement learning, a posture-synergy prior (as in EigenDexplore) shrinks a dexterous hand's search space. We ask what plays that role when the controller is code written by an agent. We gave coding agents one of six finger-command interfaces and a budget of four scored simulations, then measured their policies on held-out initial conditions across 12 manipulation tasks:
  • raw joints
  • fingertip IK
  • PCA postural synergies
  • object-centric contact primitives
  • all of these at once
  • all of these plus a grip-force servo
Agents converged on the same coordination layer whatever they were given: per-finger task-space (fingertip) control plus a reachability query and self-written feedback loops.
  • Joint-level and synergy-level agents rebuilt it themselves (10/12 each).
  • Agents offered every layer used it in 23 of 24 runs and never called synergies.
  • A force-servo layer, added because agents asked for it, cut iterations-to-solve on the solvable tasks from 12–15 to 6.
Held-out success was set mostly by the task, not the interface. The hard tasks failed on grasp shape: an unstable two-pad pinch on thin objects. Shared memory across agents opened two of them that no single agent could solve.

IIntroduction

EigenDexplore-style RL keeps the full joint action space but adds a prior built from postural synergies, the few principal components that explain most human or expert grasping postures. The prior turns undirected exploration into exploration along meaningful whole-hand motions.

A coding agent explores differently:

  • It writes a program, runs it a few times, reads metrics and a contact sheet, and edits the program.
  • Its "samples" are whole iterations, each costing minutes.
  • Its prior is whatever vocabulary the interface hands it.
The question is which vocabulary, at which level of finger coordination, lets an agent reach a robust policy in the fewest iterations. We also ask how success depends on the iteration budget, on initial-condition variation, and on memory shared between agents.

Contributions.

  • A benchmark of 12 in-hand and prehensile tasks with seeded, severity-scaled initial-condition variation.
  • Six interface levels with identical observations.
  • A budgeted agent protocol with held-out evaluation.
  • A study of 67 agent runs, with an audit of what each agent built and how it failed.
  • Evidence that the useful agentic prior is task-space fingertip control plus feedback, not a posture basis.

IIPlatform and tasks

Robot. A UR5e arm with a 20-DOF Tesollo DG5F-S right hand (5 fingers × 4 joints) is simulated in RoboSimStudio on Newton collision with the MuJoCo-Warp solver.

  • Timing: physics at 1 kHz, control at 50 Hz.
  • Fingers: weak position servos (kp 3 N·m/rad, |τ| ≤ 0.65 N·m), so they are compliant.
  • Arm: follows commanded palm poses through IK.
  • Observations: exact simulator state, the same at every level: object poses, measured palm pose, the five fingertip pad centres, and per-finger contact-force magnitudes against a named object.

Tasks. Twelve tasks (Fig. 2) range from a fingertip pinch-and-turn to in-hand pen re-orientation and Baoding balls. Each task has a scripted expert routine with privileged state, used only as a reference score. Agents could not read it.

A.Initial-condition variation

Every case is a pair seed:severity. Each task's scene.py draws its perturbations uniformly within ±(half-range × severity), consuming one draw per parameter whatever the severity. Severity 0 is the nominal scene, and severity 1 is the full range the task documents. The parameters are position, yaw, size, mass, friction and articulation friction.

  • Development cases: each iteration of an agent scores 3 fresh cases, at severities 0, 0.5 and 1. Their seeds come from a hash of task, level and iteration, so an agent can never re-run a case to cherry-pick.
  • Held-out cases: 6 fixed cases, 1000:0, 1001:0.5, 1002:0.5, 1005:1, 1006:1, 1007:1, disjoint from every development seed.

IIIMethod

A.Finger-command interfaces

All levels share the observation API and the arm (palm_pose, carry, hold). A policy is a Python generator run(api) that yields once per 20 ms step, using numpy and scipy only. The levels differ only in the finger command:

  • Joints. The agent sets 20 joint targets, q ∈ ℝ20, interpolated in joint space. There is no coordination.
  • Fingertips. The agent sets palm-frame pad positions pi ∈ ℝ3 per finger, solved by per-finger IK, with optional straight-line paths and distal-link directions. A query reach(i, p) returns the IK residual without moving.
  • Synergies. The agent sets six coefficients s. Targets are q = μ + B s, clipped to joint limits. B is a leave-one-task-out PCA of expert finger postures: the task being solved never contributes to its own basis. Six components explain about 90 % of the variance. describe() reports how each pad moves at ±1 sd.
  • Contacts. Object-centric primitives take points in the object's own frame:
    • approach and grasp bring pads to points, with a squeeze depth;
    • squeeze presses held pads further in;
    • rotate and translate move held pads rigidly as if fixed to the object;
    • release, relocate and tuck manage the other fingers.
    There is no direct finger move.
  • Layered. All of the above at once, with every call counted by layer. This is the agentic analogue of EigenDexplore's "full action space plus a synergy prior": nothing is taken away, and the higher layers are offered, not imposed.
  • Force (phase 2). Layered plus a closed-loop grip servo. grip(obj, {finger: F*}) moves each named pad along its closing direction ni every step. By default ni points at the centroid of the other gripped pads, which is the pinch line. The servo keeps running through every later motion until ungrip().
di ← clip( di + k ( Fi* − Fi ) Δt , −6 mm, 15 mm ),   picmd = pinom + di ni,   k = 8 mm N−1s−1 (1)

Here Fi is the measured contact-force magnitude between finger i and the object. The fingers are about 1.2 N/mm stiff at the pad, so this gain gives a time constant of about 0.1 s.

B.Agent protocol

Each run gives one Claude agent one task and one level (Fig. 4). The agent receives:

  • a brief;
  • the task's TASK.md: goal, objects, variation ranges and the exact success rule;
  • the level's API documentation;
  • the scorer check.py.

It may not read the expert routines, the scene source, the docs or other agents' work (except in phase 3), and may not run offline kinematics. Every simulation goes through iterate, which:

  • snapshots policy.py;
  • scores it on the three fresh development cases;
  • prints the metrics and the perturbation drawn, the last 60 lines of the api log, and optionally a 12-frame contact sheet of one case.

Only completed iterations count against the budget of 4. The stop rule is 3/3 on two consecutive iterations. At the end the agent names its FINAL iteration, and that policy alone runs on the six held-out cases.

C.Three phases

The study ran in three phases (Fig. 5).

  • Phase 1: joints, synergies, contacts and layered on all 12 tasks, plus fingertips on cube_pinch. That is 49 runs.
  • Phase 2: the force level on all 12 tasks, 12 fresh runs under an identical protocol. We added it because phase-1 agents repeatedly reported that they lacked force-regulated contact.
  • Phase 3: six fresh force-level agents on the six hardest tasks, with 6 iterations each. They were allowed to read every earlier run's notes, policies and per-case logs, plus a one-page summary of cross-task lessons. This probes the "skill update" axis: accumulated, reusable knowledge across agents rather than more iterations within one agent.

IVResults

A.Success against iteration budget

Fig. 6 shows mean development success per iteration, over the 12 tasks. A run that met the stop rule early keeps its last score.

  • Higher-level interfaces start higher: the force level scores 0.33 at iteration 1, against 0.08 for joints.
  • By iteration 4 every level sits near 0.4.

Given time, a raw-joint agent gets about as far. It pays for that with iterations, which it spends building the coordination layer it lacks (Section IV-C).

B.Held-out success and initial-condition variation

Table I gives every run's held-out score.

  • Five tasks are solved by nearly every level: cube_pinch, card_pickup, cap_twist, pen_table_slide and cube_palm.
  • Five fail at every level in phases 1–2: baoding, pen_finger_roll, pen_pickup_pivot, pen_writing_grasp and scissors.

Pooled over tasks, the levels sit at 0.35–0.49 held-out success. That spread is within noise at six cases per run, and the outcome is dominated by the task.

Fig. 7 splits held-out success by severity. It is flat or even rising with severity, because the severity-1 cases are half the held-out set. When a policy fails, it fails at every severity: the failures are structural, not a matter of robustness. The one exception confirms the rule:

  • cube_palm's contact-primitive policies failed on larger-than-nominal cubes, because the primitives ignore object size.
  • The force servo removed that sensitivity: 3/3 at every severity and 5/6 held out.

C.What agents built: the agentic synergy

We audited every run's notes and code.

  • Joints level: 10 of 12 agents first built a fingertip layer inside policy.py. Seven used finite-difference Jacobian IK on measured pads with Broyden updates; three fitted a multilinear or product-of-exponentials forward model.
  • Synergies level: 10 of 12 built a synergy-to-fingertip model and solved for coefficients. 11 of 12 reported coupling, an unreachable thumb, or a nonlinear map beyond about 1 sd.
  • Contacts level: 5 of 12 rebuilt "put this pad here" out of approach.
  • Layered and force levels: agents used fingertips in 23 of 24 runs and synergies in none (Fig. 8).

Synergies helped only where a single whole-hand scalar fit the task, such as a grasp-to-open dial for cube_palm or a flexion sweep for cap_twist.

The useful prior for an agent is therefore a representation, not a reduction:

  • per-finger Cartesian targets in the palm or object frame;
  • a cheap feasibility query;
  • object-frame primitives for whole-grasp motion;
  • closed-loop wrappers the agents write themselves, such as force bands, stop-on-contact moves and scorer replicas.

Those wrappers accumulate across iterations and, in phase 3, across agents. They are the skills.

D.Why hard tasks fail

The audit puts the 49 phase-1 runs into failure categories (Fig. 9, left). Sixteen ended in a working policy. The largest failure category, also sixteen runs and fifteen of them pen tasks, is a physical grip limit:

  • A thumb–index pinch on a 7.5 mm pen acts as a hinge about the pad line, and the pen squirts sideways under shear or tilt.
  • Force control fixes the force but not this, because the destabilising couple grows with grip force.
  • The one pen task solved by many levels was solved with a third contact: a V-cage of thumb against index and middle, or a bore wall as a brace.

The second recurring limit is geometry the API does not expose:

  • reach checks pad centres only, so planned grasps collide through finger links.
  • The fingertips are thicker than the pen, so contacts sit above its equator.

The capabilities agents most often said were missing (Fig. 9, right) are a map of the next interface layers.

E.Phase 3: memory across agents

Phase-3 agents were the first to read other agents' work. They copied whole phase sequences, monitors and mock APIs, and turned earlier failure diagnoses into designs (Table II).

  • pen_finger_roll went from 0/6 for every earlier agent to 6/6. An earlier note had suggested that the swing axis should be the pinch's free hinge. Building on that, the new agent held the pen between the index and middle fingers, squeezed by their abduction joints under the grip servo, and rotated the palm about the knuckle axis while the fingers counter-rotated.
  • pen_gravity_pivot reached 4/6. It took the layered agent's pivot nearly verbatim and added a servo on the hinge pinch plus a third finger closed into the measured gap.

Within one agent, iterations past about 3 bought little (Fig. 6). Across agents, written notes plus reusable helpers worked like skill updates.

VILimitations and protocol deviations

  • Small numbers. 4 iterations and 6 held-out cases per run make differences of one or two cases noise. The clear signals are the speed and usage patterns, not pooled success.
  • Changes mid-study. The study was paused once. Many phase-1 runs were finished by a second agent reading the first agent's notes. The budget was cut from 8 to 4 iterations and the held-out set from 10 to 6 cases partway through. The fingertips level ran only on cube_pinch.
  • Rule deviations found in the audit:
    • 18 agents read partial results of killed, uncounted iterations;
    • 2 ran iterations concurrently;
    • 6 fitted models offline from logged api data;
    • 3 read the hand's model or mesh files for link geometry.
    No policy used private API or forbidden imports.
  • Force-servo defects reported by agents:
    • it silently saturates at its travel limit;
    • directions given in the object frame rotate with the object;
    • it regulates only force magnitude, so a stray contact can satisfy it;
    • grip() reports "settled" at 0 N for targets at or below 0.3 N;
    • it does not resist twisting about the pinch line.
  • Simulation only. Contact, friction and fingertip geometry are simulator approximations. Several failure modes, such as pen squirt and link collisions, depend on them.
